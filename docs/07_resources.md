# Управление ресурсами проекта

## 1. Распределение ролей в команде
В проекте задействована команда из 4 человек. Каждый участник совмещает управленческую роль с ролью разработчика, чтобы обеспечить взаимозаменяемость и полное погружение в проект.

| Участник | Основная роль | Зона ответственности в коде | Зона ответственности в документации |
|----------|---------------|-----------------------------|-------------------------------------|
| **У1** (Тимлид) | Менеджер проекта / Backend-разработчик | Аутентификация (JWT), настройка CI/CD | Устав проекта, методология, реестр рисков |
| **У2** | Бэкенд-разработчик / Аналитик | База данных (SQLAlchemy), CRUD задач, миграции | Требования (User Stories), PERT, управление ресурсами |
| **У3** | Frontend-разработчик / Тестировщик | Основной UI (React), интеграция с API | План тестирования, UI-прототип |
| **У4** | DevOps / Frontend-разработчик | Docker, docker-compose, формы авторизации | Анализ стейкхолдеров, инструкция по развертыванию |

## 2. Матрица ответственности (RACI)
Матрица RACI показывает степень участия каждого члена команды в ключевых задачах проекта:
- **R** (Responsible) — непосредственно выполняет работу.
- **A** (Accountable) — несет ответственность за результат (утверждает).
- **C** (Consulted) — консультирует, предоставляет информацию.
- **I** (Informed) — информируется о ходе работ.

| Задача / Роль | У1 (Тимлид) | У2 (Бэкенд) | У3 (Фронтенд) | У4 (DevOps) |
|---------------|-------------|-------------|---------------|-------------|
| Настройка репозитория и CI | **A/R** | I | I | C |
| Проектирование БД (ER) | A | **R** | I | I |
| Разработка API задач | A | **R** | C | I |
| Разработка UI (React) | A | C | **R** | C |
| Настройка Docker | A | I | C | **R** |
| Написание отчета | **A/R** | C | C | C |
| Тестирование системы | A | C | **R** | **R** |

## 3. Гистограмма загрузки ресурсов (в неделях)
На основе нашего плана (PERT), мы распределили нагрузку так, чтобы избежать перегрузки одного участника.

| Участник | Спринт 1 (Неделя 1) | Спринт 2 (Неделя 2) | Спринт 3 (Неделя 3) |
|----------|----------------------|----------------------|----------------------|
| **У1** | Высокая (настройка инфраструктуры) | Средняя (Auth, CI) | Низкая (ревью, отчет) |
| **У2** | Высокая (БД, требования) | Высокая (API, тесты) | Средняя (документация) |
| **У3** | Средняя (прототип UI) | Высокая (верстка) | Средняя (тестирование) |
| **У4** | Средняя (Docker, анализ) | Высокая (Docker, Auth UI) | Средняя (финальный деплой) |

## 4. Выравнивание ресурсов
Для предотвращения выгорания и простоев:
- Если У2 перегружен задачами по БД, У1 помогает с кодом (так как он тоже бэкенд-разработчик).
- Если У3 заканчивает верстку раньше, он подключается к написанию тестов (совместно с У4).
