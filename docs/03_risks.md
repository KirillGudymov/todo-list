# Реестр рисков проекта

| ID | Риск | Вероятность (1-3) | Влияние (1-3) | Оценка (В*В) | Стратегия реагирования |
|---|---|---|---|---|---|
| R1 | Участник команды заболел | 2 | 2 | 4 | Распределить задачи с запасом. Перекрестное ревью (каждый знает код хотя бы одного другого участника). |
| R2 | Конфликты при слиянии веток в Git | 3 | 1 | 3 | Делать частые коммиты. Ежедневно синхронизировать `develop` перед началом работы. |
| R3 | Несовместимость версий Docker на ОС участников | 2 | 2 | 4 | Использовать `.env` файлы и зафиксировать версии в `docker-compose.yml`. |
| R4 | Срыв сроков из-за учебы | 3 | 3 | 9 | Использовать методологию Kanban. Взять самую простую архитектуру (MVP). Разбить работу на мелкие задачи. |
| R5 | Изменение требований преподавателем | 1 | 3 | 3 | Зафиксировать рамки проекта (Scope) в Уставе. Выделить буферное время в конце. |
