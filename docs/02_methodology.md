# Обоснование выбора методологии

## Выбранная методология: Kanban
Для реализации проекта выбрана гибкая методология **Kanban**. Это обусловлено следующими факторами:
1. **Малый размер команды (4 человека):** Нет необходимости в жестком распределении ролей (Scrum Master, Product Owner), как в Scrum.
2. **Переменная загрузка:** Учебный процесс накладывает ограничения, Kanban позволяет гибко перераспределять задачи в зависимости от доступного времени участников.
3. **Быстрая обратная связь:** Работа ведется небольшими итерациями, что позволяет быстро выявлять ошибки.

## Инструменты
Для визуализации процесса используется **GitHub Projects (Board)** со следующими колонками:
- **Backlog** — все задачи проекта.
- **To Do** — задачи, готовые к выполнению в текущем спринте.
- **In Progress** — задачи в работе.
- **Review** — задачи, ожидающие код-ревью (PR).
- **Done** — завершенные задачи.

## Правила работы с Git
1. Прямые пуши в `main` и `develop` запрещены (настроена защита веток).
2. Каждая задача выполняется в отдельной ветке: `feature/<название>` или `docs/<название>`.
3. Слияние изменений происходит только через Pull Request (PR).
4. Каждый PR должен пройти ревью (минимум 1 Approve) от другого участника команды.
